# 前端编码与接口规范 (Coding Guidelines)

为了保证前后端分离架构的纯粹性，并为日后无缝接入真实后端服务做好准备，本项目所有参与开发的成员（含 AI 助手）在进行业务逻辑开发时，必须严格遵守以下核心守则：

## 1. 强制 API 驱动 (API-Driven Development)
**任何涉及到数据的「增、删、改、查 (CRUD)」操作，必须通过调用 API 接口完成，严禁在前端直接操作本地状态（如直接 push 数组）而不通过网络请求。**

- **即便是使用 Mock 数据**：即便目前后端接口尚未开发完成或处于使用 MockJS / MSW 模拟的阶段，也必须将 Mock 做在网络请求拦截层。组件内部必须调用 `axios` 或 `fetch` 发起真实的 HTTP 请求。
- **无缝切换**：这一守则的唯一目的是为了保证将来接入真实后端时，只需要更改 `baseUrl`（即换一下 IP 和端口），前端所有的业务逻辑、Loading 状态处理、错误捕捉等均不需要改动一行代码。

## 2. 状态更新规范
当用户触发一个更新操作（如：点击添加、修改状态、删除）时，标准的工作流必须是：
1. **触发行为**：UI 组件收集用户输入，调用对应的 `api.ts` 中的异步函数（如 `api.post('/todos', data)`）。
2. **等待响应**：使用 `await` 或 `.then()` 等待网络请求返回成功（HTTP 200/201）。
3. **更新视图**：**只有在 API 确切返回成功响应后**，才允许更新前端 Vue 的响应式状态（如 `todos.value.push(res.data)`），从而驱动视图更新。若请求失败，则进入错误处理逻辑并抛出异常提示，绝不能提前乐观更新（除非有极特殊的需求且提供了回滚逻辑）。

## 3. 目录与隔离规范
- **组件层 (`src/components/`, `src/views/`)**：只负责视图渲染和事件抛出 (`emit`)，或者接收外部传入的 Props，不应当包含具体的 API url 拼接逻辑。
- **接口层 (`src/api/`)**：所有与后端交互的请求必须统一封装在这里，每个模块（如 `todo.ts`, `schedule.ts`）各自独立。组件只能通过引入这里的函数来发起请求。
- **模拟层 (`src/mock/`)**：Mock 逻辑必须被限制在这个文件夹内。业务代码里不允许出现 `if (isMock)` 这样的强耦合判断代码。

## 4. 后端接口文档同步机制
- **持续更新接口契约**：后续开发中，只要涉及到新增 API 调用操作（或修改现有 API 请求/响应结构），在编写前端网络请求代码的同时，**必须强制查看并更新**根目录下的 `BACKEND_API_GUIDELINES.md` 文档。
- **文档即契约**：前端发起的一切网络请求，都必须以该文档中的定义为准，以方便后端工程师直接按此文档开发真实的后端服务。

> **给 AI 的强制指令**：在之后的每一次需求迭代和代码编写中，如果涉及到状态交互，你必须在心中默念并严格执行上述规范，杜绝“直接在本地修改变量来伪造交互”的偷懒行为。同时，任何涉及到 API 变动的改动，都必须同步更新后端接口指导文档！
